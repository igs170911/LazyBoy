# 深度研究

使用者要「研究／調查／比較／整理報告／查清楚」，或一個問題需要 5 個以上來源才答得好時使用。簡單的事實查詢直接 `web_search` 就好，不要用這個流程。

## 1. 拆題與計畫

先用 `todo` 寫下 3 到 6 個彼此獨立的子問題，最後一項固定是「交叉比對並寫報告」。子問題要具體，例如「A 產品 2026 年的價格與方案」，不要寫「了解 A 產品」。

範圍不清楚（地區、時間、預算、要比較哪些對象）時，先用 `clarify` 問一次，不要猜。

## 2. 平行查證

用 `delegate_task` 一次交出所有子問題，每個子問題一個 task：

```
delegate_task(tasks=[
  {"goal": "<子問題 1>", "context": "使用繁體中文。用 web_search 找來源，用 web_extract 讀原文，至少讀 2 個獨立來源。回傳：重點結論（含數字與日期）、每個結論對應的來源網址、彼此矛盾或無法確認的地方。"},
  {"goal": "<子問題 2>", "context": "<同上>"}
])
```

- 需要登入或互動的網站不要交給子 agent，自己用 `browser_exec` 處理。
- 有子 agent 失敗或結果太薄時，自己針對那一題補查，不要整批重跑。

## 3. 交叉比對

- 同一事實有兩個以上獨立來源才寫成確定；只有一個來源標「單一來源」。
- 來源互相矛盾時兩邊都寫出來，並說明哪個較新或較可信。
- 數字一律附日期與來源；查不到的明確寫「未取得」，不要估計後當成事實。

## 4. 交付

- 報告寫成 `/workspace/reports/<主題>-<YYYY-MM-DD>.md`：結論摘要、各子問題的發現、比較表（三項以上才用表格）、未確認事項、來源清單（標題與網址）。
- 對話只回 3 到 5 行：最重要的結論、報告路徑，以及還不確定的地方。
