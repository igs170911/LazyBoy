# 聊天體驗改進計畫（2026-10）

## 目標

將 LazyBoy 的單機器人聊天體驗打磨成如同常駐個人助理：即時回應、簡潔溫暖、主動完成、穩健可靠。

## 改進項目

### 1. 即時確認（Instant Acknowledgement）

**目標**：使用者送出訊息後 2 秒內必須有回應。

**實作方式**：
- 簡單問題直接回答
- 需要多步驟工作時，先用一句話確認收到並說明第一步
- 在 SOUL.md 中明確要求：「使用者送出訊息後，**兩秒內必須回應**」

**範例**：
```
使用者：搜尋今天的科技新聞，整理三則重點
Bot（即時）：收到，我先搜尋最新科技新聞，再整理重點給你。
Bot（稍後）：[實際搜尋結果與整理]
```

### 2. 智能路由（Smart Routing）

**目標**：輕量對話用快速便宜的聊天模型，工具工作用能力強的工作模型。

**現況**：
- `server/routing.py` 已實作模型分流
- 支援語意分類器判斷意圖
- 已有 deterministic_intent 處理明確關鍵字

**改進方向**：
- 確保簡單問候、查詢不啟動工具
- 分類器更準確區分閒聊與工作
- 背景任務不阻塞新對話

### 3. 里程碑進度更新（Milestone Progress Updates）

**目標**：只顯示有意義的進度，隱藏工具級細節。

**實作**：
- 前端 `WorkCard` 組件已支援摺疊步驟（預設只顯示最新一步）
- SOUL.md 中要求：「進度更新只在重要里程碑回報」
- 好範例：「找到 5 篇相關文章，正在比對內容」
- 避免：「正在執行 web_search」「正在讀取網頁」

**UI 行為**：
- 工作中預設顯示「思考中」+ 最新一步
- 點擊可展開查看完整步驟與旁白
- 完成後摺疊為「已思考 Ns · N 個步驟」

### 4. 主動完成（Proactive Completion）

**目標**：背景工作完成時主動通知，不需要使用者追問。

**實作**：
- Runtime 的 `adopt()` 機制已支援背景工作完成回報
- SOUL.md 中要求：「**完成後主動回報**，不要等使用者問」
- 支援瀏覽器推播通知（PWA 已支援）

**行為**：
```
Bot：正在背景處理 3 項子任務...（使用者可以繼續做其他事）
[稍後自動]
Bot：剛才的 3 項任務都完成了，結果整理如下...
```

### 5. 清晰訊息渲染（Clean Message Rendering）

**現況**：
- Markdown 支援完整（標題、清單、表格、程式碼）
- 支援圖片、檔案預覽
- 支援回覆引用（reply-to）

**改進方向**：
- 工具步驟預設摺疊（已實作）
- 支援多則短訊息拆分（可選）
- 決策問題渲染為按鈕（QuestionCard 已支援）

### 6. 決策問題按鈕化（Decision Questions as Buttons）

**現況**：
- `QuestionCard` 組件已支援選項按鈕
- clarify、approval 等已有專用 UI

**改進方向**：
- SOUL.md 強調多用 clarify 而非純文字問答
- 選項數量適中時優先用按鈕

### 7. Persona 調整（SOUL.md Tuning）

**已實作改進**：
- 強調即時回應：「兩秒內必須回應」
- 回覆風格：「簡潔、直接、溫暖」「先給答案或結果」
- 避免公務口吻：不說「您好」「敬請」「祝您順心」
- 自然報告：「查到了，最新的...」「完成了，檔案在...」
- 錯誤處理：先自己診斷、換方法重試，不輕易放棄
- 主動完成：「完成後主動回報」

### 8. 穩健性（Robustness）

**目標**：引擎卡住或出錯時，使用者看到清晰狀態，Bot 能自動恢復。

**現有機制**：
- Runtime watchdog（`IDLE_LIMIT`, `TOOL_IDLE_LIMIT`）
- Stop 按鈕立即停止工作
- 錯誤自動轉換為使用者友善訊息（`friendly()` in runtime）

**改進方向**：
- SOUL.md 明確要求：「工具失敗時先換方法重試，不輕易放棄」
- 連續失敗兩次同一做法才換方案
- 明確說明卡在哪裡、試過什麼、建議如何協助

## 使用者可見改進

### 對話節奏
**改進前**：送出問題後等待數秒，直接看到最終答案
**改進後**：立即確認（1-2秒），複雜工作先說「收到，我現在...」，再執行

### 回覆風格
**改進前**：「好的，我會幫您查詢相關資料...」（較正式、冗長）
**改進後**：「查到了，最新的科技新聞是...」（直接、簡潔、溫暖）

### 進度顯示
**改進前**：所有工具呼叫逐一列出，畫面雜亂
**改進後**：預設只顯示「思考中 + 最新一步」，需要時點擊展開

### 完成通知
**改進前**：背景任務完成後不會主動說
**改進後**：自動回報「剛才的任務完成了...」

### 錯誤處理
**改進前**：工具失敗後可能直接停止
**改進後**：自動換方法重試，連續失敗才說明並建議

## 測試方式

### 手動測試場景
1. **即時回應**：送出「今天天氣如何」，應在 2 秒內收到回覆
2. **智能路由**：「你好」應該快速回答，不啟動工具
3. **里程碑更新**：交辦複雜任務，觀察進度是否只顯示關鍵步驟
4. **主動完成**：啟動背景任務，確認完成時主動通知
5. **錯誤恢復**：故意讓工具失敗（例如無效網址），觀察是否換方法重試

### 自動化測試
- Runtime 測試：測試即時確認邏輯
- 路由測試：驗證簡單對話走 chat 模型
- 前端測試：Playwright 測試 WorkCard 摺疊行為

## 效能考量

- 即時確認不影響整體速度（只是先說一句話）
- 智能路由減少不必要的工具啟動，提升響應速度
- 里程碑過濾減少 UI 更新頻率
- 背景通知不阻塞主線程

## 相容性

- 保持所有現有 API 不變
- 舊 Bot 自動獲得新 SOUL.md（下次 `computers.prepare()`）
